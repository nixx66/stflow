# Arc Invoice Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace frontend mock creation and payment with typed Arc Testnet contract reads and writes, and add a safe wallet account menu.

**Architecture:** Domain helpers own deterministic ids, metadata hashes, and contract mappings. Focused hooks own transaction lifecycles; UI components render hook state without duplicating authorization rules.

**Tech Stack:** Next.js 15, React 19, TypeScript, wagmi, viem, RainbowKit

## Global Constraints

- Do not change the established visual system.
- Do not use floating-point arithmetic for USDC.
- Never mark success before a successful Arc transaction receipt and event decode.
- Never fall back to mock, demo, or browser ledger state.
- Every production change starts with a failing test.

```ts
import { encodePacked, keccak256, type Address, type Hex } from "viem";

export type InvoiceMetadata = {
  customerName: string;
  title: string;
  description: string;
  memo: string;
};

export function canonicalInvoiceMetadata(metadata: InvoiceMetadata) {
  return JSON.stringify({
    customerName: metadata.customerName.trim(),
    title: metadata.title.trim(),
    description: metadata.description.trim(),
    memo: metadata.memo.trim()
  });
}

export function hashInvoiceMetadata(metadata: InvoiceMetadata): Hex {
  return keccak256(new TextEncoder().encode(canonicalInvoiceMetadata(metadata)));
}

export function invoiceIdFromNonce(merchant: Address, nonce: bigint): Hex {
  return keccak256(encodePacked(["address", "uint256"], [merchant, nonce]));
}
```

Export the registry ABI generated by Foundry and require a valid
`NEXT_PUBLIC_INVOICE_REGISTRY_ADDRESS`; do not provide a fallback address.
